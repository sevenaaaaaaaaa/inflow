# inFlow 使用指南

> 核心定位 · Features · 具体用例。写给"想看清市场与竞品、又雇不起分析团队的超级个体",
> 也是官网改版的素材源(与本 README 同源维护)。

## 核心定位

**inFlow 是面向超级个体的全域监测洞察系统:把散在十几个数据源里的信号接到一个地方,自动盯、自动算、自动告诉你该干什么。它是进阶层单件——你在用 OpenFlow 后长出"外部情报"需求时装它,不装 OpenFlow 它也完整成立。**

「竞品是不是又降价了?」「我的品牌词最近被谁在提?」「官网哪一步在漏客户?」这些问题的答案散落在十几个工具和数据源里,普通团队既没人力天天盯,也没精力拼到一起。inFlow 每条洞察都带证据、置信度和推荐动作,不是一句"建议关注"。

它也不是又一个报表看板。看板告诉你"发生了什么",inFlow 回答"所以呢":洞察强制携带推荐动作,动作直接落到自动化任务、内容任务或任意 Webhook,14 天验证窗口回查效果,模型按命中率自我调优。监测对象也不限于网站——品牌词、话题、竞品、行业事件、账号都能盯,不要求你有域名。v1.0.0 已完成商业交付(首个付费客户签约),800+ 自动化测试。

## Features(按你将真实用到的顺序)

### 1. 第一天:建工作区、接第一个源
`insflow init` → `insflow workspace create` → `insflow serve`,打开控制台 `:8400/console` 按接入向导接一个数据源(免费起步推荐 GDELT 品牌提及监控),洞察流里很快出现第一批带证据的洞察。

### 2. 每天早上:流量诊断
从 GSC / GA4 找出高曝光低点击的捡漏词、漏斗里流失最狠的一步,并给出先修哪个的排序。命令行党一条 `insflow run diagnosis`。

### 3. 盯品牌:舆情监测
品牌词 / 话题在全网新闻的提及量时序 + 情绪分布(中英双语情感词典),异常热度与负面自动预警。

### 4. 盯对手:竞品情报
定时抓竞品定价页 / Changelog,价格异动和大改版经语义 diff 自动生成洞察,不用人工刷竞品官网。

### 5. 盯客户:旅程断点
GA4 漏斗事件自动计算相邻步断点,流失预警直接触发动作,断点不靠人翻报表发现。

### 6. 没有现成模型?自己写一个
运营写一段 JSON 规则(latest / any / trend 三窗口)就是一个新洞察模型,静态校验兜底;数据成熟度评估先告诉你基础在哪一级,再决定补什么。

### 7. 问一句:数据洞察 Agent
6 个内置 Skill(竞品异动 / 流量归因 / 市场之声 / 旅程断点 / 增长实验 / 周报撰写),`insflow agent ask "竞品最近有什么动作"` 直接给结论、带证据。

### 8. 让洞察落地:动作适配器 + 14 天验证
6 个动作适配器(OpenFlow / MFlow / 飞书 / Slack / 通用 Webhook)承接推荐动作,验证窗口到期出验证报告,反馈模型效果——闭环自己转。

## 具体用例(可直接照抄的实战路径)

### 用例 A · 晨报选题(自媒体 / 独立顾问)
1. 按接入向导接 GDELT(品牌 / 话题提及)+ GSC(自己的站);
2. 每天早上打开控制台洞察流:昨日异常热度、捡漏词清单,每条带证据;
3. 看中的洞察点推荐动作 → 派成内容任务或推到飞书;
4. 周五 `insflow report weekly` 生成周报,定时送达。
**结果**:选题从"每天现想"变成"每天有带证据的候选清单"。

### 用例 B · 竞品内容节奏监控(SaaS 独立开发者)
1. 建竞品监测:Firecrawl 抓对手定价页与 Changelog,cron 定时跑;
2. 对手改价格、发新功能 → 语义 diff 自动生成洞察推送;
3. 顺着推荐动作决定:跟进发文、调整定价页,还是先不动。
**结果**:对手动静当天知道,不用每周手动刷官网。

### 用例 C · 舆情预警(有品牌要护的人)
1. 建品牌词监测主体(不需要有网站);
2. GDELT 全网新闻扫描,讨论量时序与情绪分布自动算;
3. 负面信号经飞书 / Slack 即时推送,附证据链接。
**结果**:品牌被提、被夸、被骂,你不再是最晚知道的人。

### 用例 D · 自定义洞察模型(有自己打法的操盘手)
1. 先跑数据成熟度评估,看清自己的数据基础在哪一级;
2. 写一段 JSON 规则(latest / any / trend 三窗口),定义"什么情况算信号";
3. `insflow plugin new model` 进骨架,静态校验兜底上线;
4. 14 天验证窗口到期看验证报告,命中率高的模型留下。
**结果**:行业打法变成常驻模型,而不是存在你脑子里的经验。

## 常见问题

**Q:没有自有网站 / 域名,能用吗?**
能。监测主体不只是"网站":品牌词、话题、竞品、账号都能盯;推荐起步的 GDELT 监控就不要求你有站点。

**Q:文档里的 40+ 数据源都实装了吗?**
v1.0 实装 12 个数据源插件;40+ 源矩阵是选型清单,其余按需逐个实装,接入深度以插件市场实际为准。

**Q:能爬小红书 / 微信公众号吗?**
不爬平台私域全量(走官方开放平台或数据商),遵守 robots.txt 与各 API 再分发条款——合规红线,不因需求松动。

**Q:企业级舆情源(如 Brandwatch)呢?**
属选型调研结论,需要相应商业订阅,不含在开源仓库内。

**Q:洞察会自动替我执行吗?**
inFlow 把推荐动作派给适配器(OpenFlow / MFlow / Webhook 等);对 MFlow 只创建任务绝不代发布,发布永远停在人工授权。

**Q:部署要求高吗?**
不高。SQLite + Markdown/JSON 文件存储,无消息队列、无重中间件,个人可自托管。

**Q:数据会不会被锁死在这里?**
不会。`insflow export` 支持 JSON / CSV / MD 导出,防锁定写在设计里。

## 进阶

- **配 OpenFlow**:洞察经零插件通道落 OpenFlow CDP,或走官方插件(7 个业务钩子出站、洞察回读 API),被 GrowthBrain / 画布消费;互通只走公开 API,拔掉任何一侧 inFlow 照常运转。
- **配 MFlow**:`mflow.create_content` 一键把洞察变产稿任务,发布结果经 webhook 回流进验证状态机。
- **扩展它**:`insflow plugin new source my-blog` 生成骨架,`insflow plugin check` 过静态校验即进调度器;Agent 能力用 Skill(Markdown + YAML)跨工具复用。
