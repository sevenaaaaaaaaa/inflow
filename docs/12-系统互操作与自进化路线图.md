## 1. 现状核对：哪些通道真的通了

| 通道 | 方向 | 机制（代码位置） | 状态 |
|---|---|---|---|
| 洞察落 OpenFlow CDP | IF → OpenFlow | `actions/router.py` `OpenFlowWebhookAdapter`（HMAC → `/api/webhook.php`） | ✅ 通（需配 `OPENFLOW_BASE_URL/SECRET`） |
| 内容产稿触发 | IF → MFlow | `actions/mflow_adapter.py` `mflow.create_content`（`/api/loop/create` + 轮询） | ✅ 通（打通到 `ref=mflow:loop:*`） |
| 选题登记 | IF → MFlow | `mflow.register_topic`（`/api/item/upsert` + `advance`） | ✅ 通 |
| 发布结果回流 | MFlow → IF | `actions/ingest.py` `content.published/failed` → 动作进入验证状态机 | ✅ 通（HMAC 校验 + 关联 insight） |
| 行为/成交事件回流 | OpenFlow → IF | `ingest.py` `cdp_event/lead/contact` → **仅 `bus.emit("external.event")`** | ⚠️ **断**：只进事件流，未落 `metrics` / `journey_events`，模型（LTV/RFM/旅程）吃不到 |
| 模型建议的自动化动作 | IF → OpenFlow | 4 个模型产出 `action_type="openflow.automation"`（aarrr / competitor_momentum / ltv_cac / growth_models） | ❌ **断**：ActionRouter 未注册该适配器 → 派发即失败 |
| 插件专用通道 | IF → OpenFlow | docs/04 表格中的 `openflow.plugin_api` | ❌ 未实现（文档超前于代码） |
| IF 读 OpenFlow 数据 | IF ← OpenFlow | `integrations/openflow/mcp_client.py`（JSON-RPC，只读白名单 6 工具） | ✅ 通（写操作走 OpenFlow 审批门） |
| IF 对外能力 | OpenFlow/任意 MCP 客户端 → IF | REST `/api/v1/*` + MCP stdio（`mcp_server/`，11 工具，写入口 `propose_action` 走审批门）+ Agent 工具 14 个（含 metric_qa/narrate/dq/attribution/lift/propose_action/save_note/recall_notes/schedule_task） | ✅ 通 |
| 通用生态 | IF → n8n/Zapier/Dify | `webhook.generic`（HMAC + 退避由对端负责） | ✅ 通 |

**结论**：4 条主通道（事件流入、动作派发、洞察回读、效果回流）中，**2 条实通、1 条半通、2 处断点**（`openflow.automation` 与 CDP 事件落库）。其余缺口是"可见性/可靠性"层面的：
- 无**集成状态页**（各通道是否配置、最近事件、失败率）——运维看不见
- 出站动作只在 `feedback_tracker` 层 retry×3 → `dead`，**无跨系统死信重放**
- 无**跨系统契约测试**（当前仅有单侧 fake 单测）
- 幂等契约未文档化（IF 侧 `dim_window_key`、窗口键；对端签名/去重策略需对齐）

## 2. 互操作总原则（先把"三条契约"钉死）

1. **事件契约**（入站方向最复杂，必须版本化）
   `{schema_version, type, occurred_at, source, entity, payload}`；`type` 采用 `<域>.<动作>` 命名
   （`cdp.event` / `cdp.lead` / `cdp.order` / `content.published` / `action.result`）。
   - 幂等：对端给 `event_id`，IF 以 `(workspace, source, event_id)` 去重（已有 metrics 窗口键经验）
   - 签名：HMAC-SHA256 over raw body（已有 `verify_signature`），**签名密钥按伙伴独立**
   - 落库：`cdp.event` → `journey_events`；`cdp.lead/order` → 一方指标（`first_party` 口径）
2. **动作契约**（出站方向）
   `{action_type, target_ref, params, idempotency_key}`；所有适配器必须：执行前落 `actions`、
   失败退避重试、超限进**死信表（可人工重放）**、结果写回 `result_json` 供验证状态机消费。
3. **查询契约**（双向只读）
   统一 MCP 工具命名 `insflow_*` / `openflow_*`，只读白名单 + 逐工具审计（已具备）。

> 关键取舍：**写操作永远经对端审批门**（OpenFlow AgentRuntime 审批、MFlow 状态机），
> IF 不直接改对端业务数据 —— 这既是安全边界，也是三方互信的基础。

## 3. 自进化设计：五环闭环（对齐 OpenFlow 的自我迭代）

```
  ①观测            ②决策              ③执行            ④验证            ⑤学习
┌────────┐   ┌──────────────┐   ┌────────────┐   ┌────────────┐   ┌──────────────┐
│ 采集/事件│ → │ 模型+DSL规则 │ → │ ActionRouter│ → │ 14 天验证/  │ → │ 阈值/权重/    │
│ DQ SLA  │   │ 权重+阈值    │   │ 审批+幂等   │   │ 增量/归因   │   │ 配方/Skill   │
└────────┘   └──────────────┘   └────────────┘   └────────────┘   └──────┬───────┘
     ↑                                                                    │
     └──────────────── 学习结果回写（下一轮决策更准）───────────────────┘
```

**① 观测层（已有 80%）**：采集 13 源、事件流、DQ SLA（新鲜度/缺口/续采）、性能基线。
补：`cdp.event` 落库、跨系统事件计数与失败率。

**② 决策层（已有 60%）**：18 个模型 + DSL 规则 + 语义层口径。
补：**可学习参数**——阈值（z/MAD k 值、告警阈值）、模型权重、动作优先级，登记为
`model_params`（含版本与来源依据），支持 A/B 与 bandit 分配。

**③ 执行层（已有 70%）**：7 类适配器、幂等窗口键、retry×3。
补：统一退避 + 死信表 + 重放 CLI；`openflow.automation` 适配器。

**④ 验证层（已有 75%）**：动作状态机（pending→dispatched→verifying→verified/dead）、
14 天验证、增量估计（自助法）、多触点归因、效果统计。
补：把"验证结论"结构化（effect_size / confidence / confounders）写入 `verification_results`。

**⑤ 学习层（已有 30%，是自进化的核心缺口）**
1. **阈值自整定**：以"验证有效率"为目标，对告警/异常阈值做网格或贝叶斯微调（护栏：单次调整 ≤20%，留版本与依据）
2. **权重再分配**：按 `model_effectiveness`（命中率 × 增量显著性）自动调整模型权重与动作优先级（可 bandit：ε-greedy / Thompson）
3. **配方挖掘（Playbook Mining）**：把"验证有效"的洞察→动作对聚类为策略配方，自动生成模板包草案（复用 `template export`）与 Skill 草案（复用 `skill_market` 格式），人工一键采纳
4. **评测门（Eval Gate）**：固定 golden set（历史洞察+已知结论）跑回归，自进化改动必须"不降级"才允许生效；不达标自动回滚（对齐 `deploy/upgrade.sh` 的健康检查思路）
5. **进化账本（Evolution Ledger）**：每次自进化动作记录 `{依据数据, 改动, 前后指标, 采纳/回滚}`，可审计可复现

**护栏（必须写死，避免"自我进化"变成自我伤害）**
- 任何自动改动**不触碰**：安全策略（RLS/权限）、数据留存、发送频控上限
- 单次参数改动幅度上限 + 冷却期（如 72h）×  人工一键回滚
- 无验证数据（样本 <N）不得调整参数；调整只对"同类指标/同类动作"生效
- LLM 可参与**提议**，不允许直接生效（提案进账本，由评测门 + 人工确认）

## 4. 路线图

### P0（1–2 周）：把断点接通 + 让互通可见 —— ✅ **已完成（2026-09-18）**
| 交付 | 状态 | 验证 |
|---|---|---|
| `openflow.automation` / `openflow.plugin_api` 适配器 | ✅ | 4 个模型产出的动作可派发；未配置时明确失败（契约测试覆盖） |
| CDP 事件落库（`cdp.event/lead/order` → 旅程事件 + 一方指标） | ✅ | `order` → `journey_events` + `order_count/order_revenue`；事件流可见 |
| 事件契约 + 幂等（`ingest_events` 唯一索引 + `INSERT OR IGNORE`） | ✅ | 重放同一 `event_id` 返回 `duplicate`，不双写（测试覆盖） |
| 集成状态页 `/console/integrations` + `/api/v1/integrations/status` | ✅ | 6 通道健康/缺配置/动作统计/最近事件/死信重放 |
| 出站死信 + 重放（`action_dead_letters` + CLI/API） | ✅ | 3 次失败 → 死信；重放留痕（成功回 dispatched） |
| 跨系统契约测试 `tests/integration/`（真实 HTTP 假对端 + HMAC） | ✅ | 7 例：OpenFlow webhook/automation/plugin、MFlow 产稿、入站落库/幂等/验签/回流 |

### P1（3–6 周）：自进化最小闭环 —— ✅ **已完成（2026-09-18）**
| 交付 | 状态 | 实现与护栏 |
|---|---|---|
| `verification_results` 结构化 | ✅ | 每次动作验证写效应量 + 自助法 95% 区间（种子固定）+ 样本量 + 混杂提示（数据质量/小样本/同期其它动作）+ 方法说明 |
| 进化账本 + 评测门 | ✅ | `evolution_runs`（提案/门禁/生效/回滚全程记账）；评测门确定性检查，不通过即 `rejected`；支持 `rollback` 恢复原值 |
| 阈值自整定（单参数） | ✅ | 候选分位按比较方向取（gt 取高分段/lt 取低分段），目标 90 天命中 3 次；**渐进护栏档位 20%/50%/100%/200%**（规则远离分布时才放宽，仍须门禁+人工 apply）；告警评估直接消费覆盖值 |
| 模型权重再分配 | ✅ | 由验证有效率驱动（拉普拉斯平滑 + 显著性加权），单模型 ±20% 内；`ModelRouter` 按权重排序/过滤并暴露 `weight`，`rank_insights` 用「严重度 × 权重」排序洞察 |
| 配方挖掘 v1 | ✅ | 从验证结论按 `insight_type × action_type` 聚类（样本 ≥3 且有效率 ≥50%）；产出 template-pack 兼容草案（含证据）+ `insflow playbook` + API + 控制台页 |
| 控制台与调度 | ✅ | `/console/evolution`（账本/门禁/生效/回滚/配方一键挖掘）；每周一 05:20 自动提案（**只提案不生效**） |

**验证闭环最后一公里（P1 前置，本轮补齐）**
- 此前 14 天验证**从未真正执行**：调度 `feedback.evaluate` 未传 `metrics_provider`（current={} → 全部跳过）；
  UI 派发也不落库/不记基线 → 无验证窗口可评估
- 现补齐：`compute_baseline()`（派发前 14 天**日均**口径，显式写入 baseline_json）；
  `default_metrics_provider()`（按同口径算动作后日均；**老格式裸数字自动跳过**，宁可不出结论也不出错的结论）；
  `POST /api/v1/actions` 派发后落库（pending→dispatched 状态机）并记录基线+验证窗口；
  `insflow verify run|summary` 可手动触发；调度任务已接 provider
- 线上实测：到期 4 个 → 完成 4 个 → 结构化结论 6 条（有效 1 / 显著 3）→ 权重提案 1 个
  → 门禁通过 → 生效 → 回滚，全链路闭环

**本次实测发现并修掉的问题**
- 阈值提案对 `lt` 规则方向反了（用高分位 → 越调越频繁）；改为按方向选候选分位
- 20% 硬护栏让"远离分布的阈值"永远无提案；改为渐进档位并让门禁按档位校验
- CLI 同一命令里两次 `run_async`（各起事件循环）导致 `Database not connected`；合并为单次异步函数

## 5. 指标（北极星 + 护栏）

**北极星**：**有效动作数 / 周**（= 经 14 天验证且增量显著的动作为准）

| 层级 | 指标 | 现状基线 | P1 目标 |
|---|---|---|---|
| 洞察质量 | precision@5（派发后有效比） | 待测（已有 `get_feedback_stats`） | +10% |
| 闭环时延 | 洞察→动作→验证完成 | 14 天窗口（设计值） | 首条验证 ≤10 天 |
| 数据可信 | 新鲜度 SLA 达标率 | DQ 面板可见 | ≥95% |
| 互通可靠 | 四通道动作成功率 | 未度量 | ≥99%，死信可重放 |
| 自进化 | 自动改动采纳率 / 回滚率 | 0（未做） | 采纳 ≥60%，误伤回滚 <10% |

**护栏**：误报率（告警）、动作死信率、单租户成本、发送频控超限次数。

## 6. 明确不做（边界）

- 不做通用 CDP（埋点 SDK/身份图/受众激活）与通用 BI（拖拽建模/连接器生态）——差异化在**闭环与验证**
- 不做绝对流量估算（无面板数据，只给相对指数与置信区间）
- 不自动对外发送未经审批的动作；LLM 只提议不决策
- 自进化不触碰安全/合规/频控参数
