# Insight Flow 十维进化评审（2026-09-18）

> 方法：对每一维先看**代码事实**（不是文档设想），再给差距与可验收动作。
> 结论先行：**易用/敏捷/自我进化**已有骨架，缺"最后一公里"的体感；
> **AI native / 开放 / 可定制**是当前最大的结构缺口；**兼容 / 生态 / OPC** 取决于前三者。

---

## 1) 更易用（体感 ≤ 3 步）

**已有**：接入向导、⌘K 问数、即席探索、面包屑、PWA/移动端、演示数据、空状态。
**差距**（实测）：
- 试用路径要 4 步（venv → 依赖 → .env → demo seed → 起服务），**没有一条命令**
- 首次进入没有"该干什么"的引导清单；空状态多是纯文案（无 CTA）
- 集成失败信息是原样透出（如 `HTTP 405`），对非工程用户不友好
**动作**
1. `insflow quickstart`：起服务 + 灌演示数据 + 打印/打开本地地址（一条命令跑起来）
2. 仪表盘「首跑清单」：接入第一个源 → 跑一次诊断 → 派发一个动作 → 看验证结论（打钩即消）
3. 空状态统一加 CTA（去接入向导 / 去创建监控 / 去看模板包）
4. 集成错误人话化：405/超时/未配置 → 给出"下一步该改哪个变量"

## 2) 更敏捷（改一处，分钟级到线上）

**已有**：CI（ruff/单测/MySQL/E2E/Node UI）、`deploy/sync.sh`（重启+健康检查+资源版本核对）、
`upgrade.sh` 失败回滚、进化门禁、内容哈希缓存失效。
**差距**：无**运行期开关**（一次上线只能整包回滚）；无灰度/金丝雀；无 CHANGELOG/deprecation 政策。
**动作**
1. 运行期特性开关：`/api/v1/flags` + 工作区设置覆盖（默认值来自环境），新功能可先关后开
2. `deploy/sync.sh --canary`：先同步到备用端口（8401）跑冒烟，绿了再切 8400
3. 自动 CHANGELOG（按提交类型生成）+ API 弃用政策（`Sunset` 头 + 版本保留 N 个）

## 3) 更自我进化（P1 已闭环，下一步是"结构进化"）

**已有**：结构化验证（效应量/CI/混杂）、进化账本 + 评测门 + 回滚、阈值自整定、模型权重、
配方挖掘、每周自动提案（只提案）。
**差距**（实测）：
- 进化的对象只有**参数**（阈值/权重），没有**结构**（新增指标/规则/看板草案）
- 评测集来自历史验证结论：样本少时几乎无法提案；apply 之后**没有 N 天复盘**写回账本
- 没有把"用户行为"（谁看了什么、导出了什么）作为进化信号
**动作**
1. 结构提案：从配方挖掘直接产出**监控/DSL/看板草案**（人工一键采纳，复用 template apply）
2. 复盘闭环：apply 后第 14 天自动回写 `{指标变化, 是否回滚}` 到账本 → 形成"提案准确率"
3. 行为信号：面板浏览/导出/订阅计数 → 建议默认布局与默认指标（本地统计，不上传）

## 4) 更 AI agent（能办事，不是只回答）

**已有**：10 个 Agent 工具（问数/叙事/数据质量/归因/增量/洞察检索）、MCP 9 工具（stdio + HTTP）、
技能库（6 个 Skill）、引用溯源、LLM 预算账本。
**差距**：Agent **只读**——不能起草动作进审批；没有会话记忆（多轮/工作区笔记）；
没有"Agent 定时任务"（把一段分析变成 cron）；MCP 无写工具（连审批门都没有入口）。
**动作**
1. `propose_action` 工具：产出**待审批动作**（进 pending + 通知），人点一下才派发（合规且实用）
2. 工作区记忆：`agent_notes`（Agent 读写，带引用与版本），让多轮对话有上下文
3. Agent 任务：把一次成功的问答/叙事存成**定时任务**（每日/每周跑并推送）
4. MCP 写工具白名单 + 审批门（与 1 同一条链路）

## 5) 更 AI native（LLM 是内核，不是插件）

**已有**：LLM 网关 + 预算、语义层（口径/血缘）、自动叙事、NL 问数（无 LLM 可用）、
Skill 注入 prompt、结构化输出（工具调用）。
**差距**（实测）：
- **无向量检索**（`embedding/vector` 全仓 0 命中）：洞察/报告/技能只能靠关键词
- 无 prompt 版本管理与答案评测（改了 prompt 无法回测）
- 无模型路由（成本/质量分层）、无流式输出（SSE 未接 Agent）
**动作**
1. 语义检索：SQLite 侧轻量向量（字符 n-gram + 余弦，或可选调用 embedding API）+ `search_insights`
2. Prompt 版本化：`prompts/` 目录 + 版本号 + 用 golden set 做**答案质量回归**
3. 模型路由：便宜模型做抽取/分类，强模型做推理（预算内自动降级）
4. Agent 答案 SSE 流式（复用现有 `/api/v1/stream` 通道）

## 6) 更开放（别人的系统能"接得进来、带得走"）

**已有**：OpenAPI 3.1（`/api/v1/openapi.json`）、MCP（stdio + HTTP）、出站 Webhook（HMAC）、
插件注册表（13 源 + 1 动作目录）、事件入站（HMAC + 幂等）、CSV/XLSX/PNG/MD/JSON 导出。
**差距**（实测）：
- **无 SDK / 无 examples**（`examples/` 不存在）；只有仓库内文档
- **无事件目录**（事件类型散在代码与 docs/12，没有机器可读清单）
- 插件开发只有内部约定（manifest + create_plugin），**没有脚手架与开发者指南**
- OpenAPI 无契约锁定（字段改名 CI 不会拦）
**动作**
1. `examples/`：curl / Python / TypeScript / n8n / Dify / MCP 配置各一份可直接跑
2. 事件目录 `GET /api/v1/events/catalog`（type/方向/必填字段/示例）+ docs 自动同步
3. `insflow plugin new <type> <id>` 脚手架 + 《插件开发指南》（manifest 规范、plugin_check、上架）
4. CI 锁定 `openapi.json` 快照（diff 即报"破坏性变更"）

## 7) 更加可定制化

**已有**：白标（报告级：公司名/主色/页脚）、品牌设置、指标口径（语义层）、看板布局（含历史）、
行业模板包、明暗主题、嵌入（白标 + 主题参数）。
**差距**（实测）：
- 主题令牌**只在报告**生效，控制台仍是固定色板（`theme_tokens` 控制台 0 命中）
- 无自定义图表/自定义动作适配器插件入口（`plugins/actions/` 仅 1 个目录）
- 无"新建看板"（只能改现有页布局）
**动作**
1. 控制台主题令牌：工作区设置 `theme_tokens`（主色/圆角/密度）→ CSS 变量注入
2. 动作适配器插件化：`plugins/actions/*`（manifest + create_adapter），装完即出现在动作类型列表
3. 自定义看板：选择面板 → 存为工作区看板（复用 layout + datapanel + 嵌入）

## 8) 更兼容（什么环境都能跑）

**已有**：SQLite/MySQL、Redis（可选）、零构建链、PWA、打印样式、导出多格式、
hmac 签名与 MCP 标准、Python 3.12 / 依赖全部 pip。
**差距**（实测）：
- **无 i18n**（中文写死）、无时区偏好（除静默时段外一律 UTC 展示）、货币硬编码 USD
- **无文件导入**（CSV/XLSX 进一方数据；现在只能走 API 推送）
- 脚本是 bash + systemd 假设（Windows 只能 WSL/Docker，未写入文档）
**动作**
1. i18n 骨架：`zh/en` 字典 + `?lang=` + 语言切换（先覆盖导航/按钮/空状态）
2. `insflow import csv|xlsx <文件> --metric ...`（映射列 → 指标 + 幂等窗口键）
3. 工作区时区偏好（展示层格式化）、货币单位设置
4. 文档补齐 Windows/WSL 与 Docker 运行方式

## 9) 更面向生态伙伴 / 开发者 / AI 爱好者

**已有**：集成方案 docs/04、n8n/Dify 模板、插件市场页、Skill 市场（CLI/API）、MCP 工具。
**差距**：没有**五分钟可玩**的入口（要装环境、配 key）；没有 Skill 模板与提交指南；
没有公开演示环境；没有"贡献者路径"（从使用者到贡献者的台阶）。
**动作**
1. `insflow quickstart --mock`：零 key 起一套 mock 数据 + 浏览器打开（爱好者 5 分钟上手）
2. `insflow skill new` 模板 + 《Skill 编写指南》（含 6 个内置 Skill 作为范例）
3. 公开只读演示工作区（演示数据 + 白标关闭写操作）供分享
4. 贡献者指南：插件/Skill/模板包三条路径 + PR 检查清单

## 10) 更面向 OPC（一人公司 / 超级个体）

**已有**：自动化采集/洞察/日报/订阅、私有化零依赖、PWA、⌘K 问数、模板包、自进化、
代运营交付（白标报告 + 客户只读嵌入 + 审计 + 权限）。
**差距**（实测）：
- **无客户工作区快切**（多客户代运营要手动改 URL）
- 没有"今天做什么"的行动清单（洞察是流，不是待办）
- 没有**每客户 ROI/成本**视图（动作有效数 vs 采集/LLM 成本）
- 无支付通道（自助开通最后一环仍在商务侧）
**动作**
1. 顶栏工作区切换器（按账号可见工作区快切，记住偏好）
2. 「今日三件事」面板：按 严重度 × 模型权重 × 到期动作 排序，支持一键派发
3. 客户 ROI 卡：有效动作数 / 验证显著数 / 数据源成本 / LLM 成本（复用 billing + verification）
4. OPC 交付手册（一页）：从接客户到交付验证报告的 SOP

## 建议的首批（2–3 周，性价比最高）

| 批次 | 内容 | 为什么先做 |
|---|---|---|
| **A** | `insflow quickstart --mock` + 首跑清单 + 空状态 CTA | 把"能不能自己玩起来"从 30 分钟压到 5 分钟（易用 × 生态 × 爱好者） |
| **B** | `examples/` + 事件目录 API + `plugin new` + OpenAPI 契约锁定 | 开放度是可被外部验证的硬指标（开放 × 兼容 × 伙伴） |
| **C** | `propose_action` 工具 + 工作区记忆 + Agent 任务 | 让 Agent 从"会答"变"会办"（AI agent × AI native） |
| **D** | 客户工作区快切 + 今日三件事 + 客户 ROI 卡 | 直接服务 OPC 挣钱场景（OPC × 易用） |
| **E** | 控制台主题令牌 + 动作插件化 + 自定义看板 | 白标与定制的完整性（可定制 × 伙伴交付） |

推荐顺序：**A → D → C → B → E**（先让人用起来、让 OPC 挣到钱，再补开放与定制）。
