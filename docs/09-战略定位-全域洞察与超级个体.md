# Insight Flow 战略定位更新：从「网站增长情报」到「全域数据监测与洞察」

> 版本 v1.1（2026-09-16）。触发：首位客户交付后，市场反馈显示需求远大于"网站增长"。
> 本文件覆盖并对齐 docs/07 的路线图方向。

---

## 1. 定位修正

**旧定位**：面向企业的"大增长"情报与策略操作系统，优先打通 OpenFlow/MFlow。

**新定位**：**面向超级个体的全域数据监测与洞察平台**。

- **不局限于网站**：监控对象可以是任意"监测主体"——品牌词、话题、竞品、行业事件、账号、平台热榜，不要求有域名或自有站点。
- **面向更多生态的超级个体**：独立顾问、独立开发者、自媒体、跨境卖家、投研/分析师、增长操盘手——他们**不一定需要 OpenFlow 的全栈执行**，但**刚需**：
  - 数据监测（关键指标/信号变化，随时可知）
  - 舆情监测（品牌词/话题在全网的提及与情绪）
  - 多渠道数据汇总分析（一个地方看全，而不是拼 5 个工具）
- **OpenFlow/MFlow 从"前提"降为"可选增强"**：有则打通执行闭环（洞察→动作→验证），无则纯洞察交付（监测→洞察→报告）。

## 2. 能力模型（三层，与旧版本兼容）

```
L1 采集层  ── 全域 Source 插件（搜索/新闻/社媒/论坛/平台热榜/网页/第一方）
              ↑ 新增"平台型"数据源：热榜、话题、账号、榜单（不依赖自有网站）
L2 洞察层  ── 监测主体（Monitoring Subject）抽象：不再假设"网站"
              主题 / 品牌词 / 竞品 / 行业事件 / 账号 / 自定义
              → 洞察引擎（内置模型 + DSL）→ 洞察流
L3 交付层  ── 控制台 / 报告（周报·深度·白标）/ API / MCP / Webhook
              可选增强：OpenFlow 执行闭环、MFlow 内容流水线
```

## 3. 与旧路线的关系

| 旧（docs/07） | 新（本文件） |
|---|---|
| 交付即服务（R1） | 保留：备份/OAuth/体检/幂等——仍是运营底座 |
| 运行质量（R2） | 保留：摘要/告警/预警/强校验 |
| 复制扩张（R3） | 保留：模板包/一键部署/对账单 |
| **R4 SaaS 云托管** | **升级为"超级个体自助版"**：注册即用、按套餐自助、无需 OpenFlow |
| 通用生态（n8n/Dify/MCP） | 提升优先级：这是超级个体接入自己工作流的主通道 |

## 4. 新增需求（写入 R4/R5）

| # | 需求 | 说明 | 优先级 |
|---|------|------|--------|
| G-1 | 监测主体泛化 | monitor 支持 `topic`（话题）/`brand`（品牌词）/`account`（账号）等非网站主体 | P0 |
| G-2 | 多渠道聚合视图 | 一个主体 → 聚合搜索/新闻/社媒/论坛/热榜来源，统一时间线 | P0 |
| G-3 | 舆情监测强化 | 情绪分布、关键提及、异常热度、负面预警（面向品牌/个人 IP） | P0 |
| G-4 | 自助注册与自助开通 | 邮箱注册 → 建 workspace → 引导选套餐 → 立即试用（无人工） | P1 |
| G-5 | 洞察订阅与推送 | 按主体/严重度订阅，飞书/邮件/Webhook 推送（超级个体主要消费方式） | P1 |
| G-6 | 轻量集成优先 | MCP / Webhook / OpenAPI 优先于重型全栈集成 | P1 |
| G-7 | 价格分层适配个体 | 增加"个人档"（低于 Free 之上的入门付费），按监测主体数计费 | P2 |

## 5. 后台设计原则（借鉴 OpenFlow 运营台）

- 设计令牌统一（oklch 色彩 + 字阶 + 圆角/阴影），明暗双主题
- 顶栏"区域 Tab" + 分组侧栏（数据驱动），一屏一事
- 组件复用（card / 表单 / 表格 / 徽标 / Toast），零一次性样式
- 中文优先，信息密度高但呼吸感足（玻璃拟态 + 柔和阴影）

## 6. 实施顺序

1. **S1** 定位文档（本文件）✓
2. **S2** 后台重设计（借鉴 OpenFlow 运营台）
3. **R4** 从"网站增长 SaaS"转为"超级个体自助监测平台"（注册/自助/计费 + 通用生态）
4. **S3** 能力泛化：topic 监测 + 多渠道聚合 + 舆情强化
