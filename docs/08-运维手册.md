# Insight Flow 运维手册（v1.0 / R2）

> 面向私有化部署客户的运维与排障指引。目标：**备份恢复 < 10 分钟、常见故障自助排障**。

---

## 1. 日常备份与恢复

### 1.1 备份机制

| 项 | 说明 |
|---|------|
| 自动备份 | 每日 09:15 UTC 随服务调度执行（`backup.daily`） |
| 备份内容 | `insflow.db`（在线 checkpoint，WAL 安全）+ `reports/` + `events/` |
| 备份位置 | `data-backup/YYYYMMDD-HHMM/` |
| 保留策略 | 30 天，超期自动清理 |
| 手动备份 | `insflow backup` |

### 1.2 恢复流程（SLA < 10 分钟）

```bash
# 1) 列出可用备份
ls data-backup/

# 2) 恢复（危险操作，自动把当前 data/ 存为 pre-restore 快照）
insflow backup --restore-from data-backup/20260916-1434 --yes

# 3. 重启服务
systemctl restart insflow   # 或 pkill + 重新启动
```

**回退保险**：恢复动作会先把当前 `data/` 移到 `data-backup/pre-restore-*`，恢复错了可以再恢复回来。

### 1.3 验证恢复成功

```bash
curl http://127.0.0.1:8400/health   # {"status":"ok","version":"1.0.0"}
insflow workspace list              # 数据可见即恢复成功
```

## 2. 排障流程（按 `insflow doctor` 输出自查）

### 2.1 第一步总是体检

```bash
insflow doctor -w <workspace-id>
```

五项检查（环境/凭据/插件/调度/磁盘）会给出 ❌/⚠️ 与**可执行修复建议**。常见问题对照：

| 体检输出 | 根因 | 处理 |
|---------|------|------|
| ❌ 主密钥未设置 | 环境变量缺失 | 设置 `INSFLOW_MASTER_KEY` 后重启（**注意**：换了密钥旧凭据不可解密，需重新接入） |
| ⚠️ 凭据保险库：无任何凭据 | 第一方数据未接入 | 访问 `/console/onboarding` |
| ⚠️ GSC/GA4 授权即将过期 | 90 天周期将到 | 等待自动轮换；若收到轮换失败告警 → 重新走授权向导 |
| ⚠️ 调度任务 0 个 | 建了服务但没建监控 / 显式关闭 | 控制台「监控任务」页创建，或检查 `INSFLOW_DISABLE_SCHEDULER` |
| ⚠️ 事件流有失败事件 | 数据源限流/网络 | 查 `insflow insight list`；GDELT 429 → 错峰 cron |
| ⚠️ 备份：从未备份 | 未挂 daily timer | 确认服务为 systemd/调度启动模式（不是裸进程） |

### 1.2 事件流回放（定位"什么时候开始坏的"）

```bash
# 最近 100 条事件
tail -n 100 data/events/<ws>/events.jsonl | python3 -m json.tool

# 关注的事件类型
# monitor.alert        → 采集失败（含错误信息）
# action.failed/dead   → 动作失败（dead = 重试耗尽）
# source.token_refresh_failed → 授权轮换失败（critical）
# auth.token_expiring  → 授权 7 天内到期预警
```

## 3. 告警分级与响应

| 级别 | 事件 | 含义 | 响应时限 |
|-----|------|------|---------|
| CRITICAL | `quota.exceeded` | 数据源配额熔断 | 当日：确认费用口径，必要时升降套餐 |
| CRITICAL | `source.token_refresh_failed` | 授权轮换失败（客户端授权已断） | **当天**重新授权（否则监控全部停摆） |
| HIGH | `monitor.error` | 监控任务连续失败 | 24h 内排查 |
| HIGH | `action.dead` | 动作重试 3 次耗尽 | 检查目标系统（OpenFlow/MFlow）可达性 |
| MEDIUM | `action.failed` / `quality_gate_blocked` | 单次失败 | 汇总后周处理 |

告警自动出站到飞书（`INSFLOW_ALERT_WEBHOOK_URL`）；每日摘要固定推送（`INSFLOW_DAILY_WEBHOOK_URL`）。

---

## 4. 升级与回滚

```bash
./deploy/upgrade.sh v1.0.1   # 自动备份 data/ → 拉版本 → 重启 → 健康检查失败自动回滚
```

升级后必做：`insflow doctor` 确认全绿。

## 5. 数据导出（防锁定承诺）

```bash
insflow export -w <ws> -o backup/ -f json   # 全量 JSON / CSV / MD
```
