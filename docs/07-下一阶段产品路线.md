# Insight Flow 下一阶段产品路线（v1.1 → v2.0）

> 版本 v1.0（2026-09-16）。前提：首个付费客户已签约，v1.0.0 已发版。
> 本阶段的核心命题从"把功能做完"切换为"**让第一个客户成功，并把成功复制**"。

---

## 阶段判断

v1.0 已覆盖：闭环管线（采集→洞察→执行→验证）、四类监控、三入口（API/MCP/控制台）、商业化底座。
当前的瓶颈不再是功能数量，而是三件事：

1. **首个客户的部署与激活**（能不能在客户环境里稳定跑起来）
2. **运行质量**（无人值守 2 周不出事，才算产品级）
3. **价值证据**（客户能不能拿着验证报告说"这钱花得值"）

---

## R1（第 1–2 周）：让第一个客户稳定运行 —— 交付即服务

**目标**：客户环境完成私有化部署 + 接入第一方数据 + 第一份验证报告交付。

- [ ] **部署验收包**：按 `deploy/docker-compose.yml` 在客户环境跑通 + `upgrade.sh` 演练一次
- [x] **OAuth refresh_token 自动轮换**（v1.0 已知边界）：access_token 过期自动用 refresh_token 换新，失败降级告警（GA4/GSC 授权 90 天不中断） （已实现：token_manager 预轮换 + 401 降级）
- [x] **数据备份自动化**：data/ 每日快照（SQLite checkpoint + 报告目录），保留 30 天，恢复演练一次 （已实现：backup.daily + chkconfig 演练）
- [x] **首次运行体检**：`insflow doctor` 命令（环境变量/凭据/插件/调度器/磁盘五项体检，输出修复清单） （已实现：insflow doctor）
- [ ] **客户专属监控清单配置**：陪跑完成 3 竞品定价页 + 品牌词 + 2 条旅程的监控上架

**DoD**：客户环境连续运行 7 天无人工干预；《成熟度报告》+《诊断报告》+ 第一条验证结论送达客户。

## R2（第 3–5 周）：运行质量与可观测

**目标**：从"跑得起来"到"看得见、可告警、快恢复"。

- [x] **可观测性**：结构化错误日志聚合 + 每日运行摘要（采集成功率/洞察产出/验证结论）推飞书 （已实现：DailyDigestBuilder + digest.daily 09:35）
- [x] **告警分级出站**：quota.exceeded / monitor.error / action.dead → 飞书加急（复用告警链路，已具备） （已实现：alerts.hourly + 路由/升级链）
- [x] **OAuth token 过期前 7 天预警**（避免客户授权静默失效——这是 SaaS 最丢人的事故） （已实现：token.audit 09:20 主动通知）
- [ ] **备份恢复 SLA**：从快照恢复全库 < 10 分钟，写进运维手册
- [ ] 首个客户的 Top5 使用痛点清单（访谈 + events.jsonl 回放分析）

**DoD**：客户侧无感知的 30 天连续运行；拿到第一份真实的客户痛点清单。

## R3（第 6–8 周）：从 1 到 N 的复制

**目标**：把第一个客户的配置经验产品化，降低下一家的交付成本。

- [ ] **部署一键化**：docker-compose 一条命令 + 引导式 init（体检 + 首个 workspace + 向导串联）
- [ ] **模板包**：首个客户的监控配置/DSL 规则/Skill 沉淀为"行业模板包"（下一个客户选行业即带配置）
- [ ] **计费闭环打通**：用量数据 → 真实账单（Stripe/国内支付，先出对账单人工确认也行）
- [x] **多租户强化**：租户级备份/恢复 + 数据导出走量审计（代理场景多客户切换的真实测试） （已实现：RLS 策略 + 行级白名单 + 审计导出）
- [ ] 销售素材：用第一个客户的验证报告（脱敏）做案例页 + 竞品情报演示环境

**DoD**：第二个客户从签约到首份报告 ≤ 1 天人工介入；对账单口径与用量 API 一致。

## R4（第 9–12 周）→ v2.0：规模化产品化

- [x] **SaaS 云托管**（多租户行级隔离落地 + 注册/登录/SSO） （已实现：注册/登录/SSO + 多租户隔离）
- [x] **在线计费**（自助开通/升降级/账单中心） （已实现：订阅/套餐/用量/对账 CLI）
- [ ] **L3 企业源通道**（客户自有凭据接入 Semrush/Similarweb/新榜/清博——合同由商务侧推进）
- [x] **审计导出**（企业采购过合规审查用） （已实现：/console/audit + CSV）
- [x] 性能基线：单实例 1000+ 监控任务、洞察流 100k+ 行的查询基准 （已实现：insflow bench，见 docs/11）

**DoD**：云托管版可自助注册试用；企业采购清单全部勾选。

## 当前技术债清单（按优先级）

| 项 | 说明 | 处理窗口 |
|---|------|---------|
| OAuth refresh_token 手动轮换 | R1 必做 | R1 |
| collector 指标无去重窗口（同 cron 多跑会重复入 metrics） | 幂等保护 | R1 |
| 控制台无分页（洞察 >100 条后渲染变慢） | R2 体验 | R2 |
| 单进程 APScheduler 调度上限 | 路线图已有预案 | R4 触发点后评估 |
| MCP HTTP 端点未接 API Key 强校验 | 部署层反代已挡，但内核应 fail-closed | R2 |
